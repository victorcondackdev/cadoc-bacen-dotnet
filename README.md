# cadoc-bacen-dotnet

[![CI](https://github.com/victorcondackdev/cadoc-bacen-dotnet/actions/workflows/ci.yml/badge.svg)](https://github.com/victorcondackdev/cadoc-bacen-dotnet/actions/workflows/ci.yml)

BCB regulatory documents for .NET 8: Cosif account codes with check digits,
a trial balance that rolls leaf balances up the six Cosif levels, documents
**4010** and **4016** (Balancete / Balanço Patrimonial Analítico) in the
published XML layout with validation, substitution diff and filing
deadlines, and the core of the SCR document **3040** with the vencimento
buckets computed from the data-base.

It is a port of [cadoc-bacen-go](https://github.com/victorcondackdev/cadoc-bacen-go)
and the XML is **byte-identical**: the suite checks 200 codes, 40 trial
balances with their 4010/4016 output, validation findings on tampered
documents, eight years of deadlines, 300 bucket cases and 15 SCR documents
against vectors generated by the Go implementation.

No dependencies beyond the .NET 8 base class library. Trimming and AOT
compatible.

```
src/CadocBacen/
  Cosif/        CosifCode (1.1.0.00.00.00-2 / 1100000002), CosifChart, illustrative sample chart
  Contabil/     Balancete: roll-up, double-entry and memorandum checks, contra accounts, result closing
  Documents/    Doc4010: 4010 / 4016 build, parse, validate, diff, deadlines
  Scr/          Doc3040: Cli, Op, Venc buckets, DiaAtraso, IPOC, CPF/CNPJ checks
tests/CadocBacen.Tests/      unit tests and Go parity tests
samples/CadocBacen.Demo/     journal → trial balance → 4010, 4016 and an SCR 3040
tools/vecgen/                Go program that generates the parity vectors
```

## Quick start

```sh
dotnet run --project samples/CadocBacen.Demo
```

```csharp
CosifChart chart = CosifChart.Sample();          // or CosifChart.Read(File.OpenText("plano.csv"))
Balancete b = Balancete.FromEntries(chart, entries);
foreach (Issue i in b.Check()) Console.WriteLine(i);

Doc4010 doc = Doc4010.Build(Doc4010.Balancete, "12345678", "2026-10", Doc4010.Inclusion, b);
File.WriteAllText("4010.xml", doc.ToXml());
DateOnly due = Doc4010.Deadline(Doc4010.Balancete, "2026-10");       // 2026-11-18

Balancete closed = b.CloseResult(CosifCode.Parse("641000000"), CosifCode.Parse("649000000"));
Doc4010 balanco = Doc4010.Build(Doc4010.Balanco, "12345678", "2026-12", Doc4010.Inclusion, closed);

IReadOnlyList<string> problems = Doc4010.Parse(xml).Validate(chart);
IReadOnlyList<Doc4010Change> changes = Doc4010.Diff(previous, substitution);

int bucket = Doc3040.BucketFor(new DateOnly(2026, 10, 31), new DateOnly(2026, 11, 5));   // 110
```

The layout carries no sign, so `Build` rejects analytical accounts whose
balance is contrary to their nature (they must be reclassified), and
`Validate` rebuilds signs bottom-up before comparing each synthetic account
with its sub-accounts. The rules, their sources and the scope of the 3040
support are documented in the
[cadoc-bacen-go README](https://github.com/victorcondackdev/cadoc-bacen-go#40104016).

The bundled chart is **illustrative**, not the official elenco de contas.
